# narezki — прототип нарезчика стримов GTA 6

Делает из горизонтального стрима один вертикальный клип 1080×1920 (30–40 с) со звуком.

```bash
./run.sh            # sample.mp4 в корне → режет его; иначе генерирует тестовый исходник
```

Для реального стрима укажите регионы вебки и таймера в координатах исходника:

```bash
CAM=1400:760:500:300 TIMER=20:20:380:80 ./run.sh
```

Что делает `narezchik.py`:
1. FFmpeg-анализ: RMS звука по секундам (`astats`) + динамика картинки (`scdet`).
2. Выбор одного цельного окна 30–40 с с максимальной активностью (+ контекст до/после).
3. Рендер: вебка сверху (1080×608), геймплей снизу (центральный кроп 1080×1312),
   увеличенный таймер поверх геймплея, прожжённые субтитры.
4. Проверка через ffprobe (разрешение, длительность, аудиодорожка) → `output/clip.json`.

Субтитры: `<исходник>.srt` или `--srt`; если установлен `openai-whisper` — расшифровка автоматически.

## Публикация в TikTok (локально)

Для публикации через интерфейс TikTok Studio нужны Node.js 20+, установленный Playwright и его Chromium:

```bash
npm install
npx playwright install chromium
PUBLISH_TIKTOK=1 TIKTOK_CAPTION="Подпись к ролику #gta6" ./run.sh
```

При первом запуске откроется браузер: войдите в TikTok вручную. Сессия сохраняется локально в `work/tiktok-profile` и используется при следующих запусках. После загрузки видео проверьте его и подпись; публикация произойдёт только после ввода `PUBLISH` в терминале. Без `PUBLISH_TIKTOK=1` поведение `run.sh` не меняется.

Можно опубликовать уже готовый файл отдельно:

```bash
npm run publish:tiktok -- output/clip.mp4 --caption "Подпись к ролику"
```

Для нескольких готовых видео положите MP4 в `queue/`. Для каждого ролика можно добавить рядом одноимённый `.txt` с подписью; если файла с подписью нет, используется имя видео. Очередь сортируется по имени файла, после успешной публикации MP4 и его `.txt` перемещаются в `queue/published/`, чтобы не отправить их повторно. Первый ролик публикуется сразу, остальные — с паузой в 60 минут:

```bash
npm run publish:tiktok:queue
```

Пауза и папка настраиваются параметрами:

```bash
npm run publish:tiktok:queue -- --folder queue --delay-minutes 60
```

Очередь покажет список роликов и попросит один раз ввести `START`; затем она публикует без дополнительных подтверждений. Оставьте компьютер и терминал включёнными до завершения очереди. Если публикация не подтверждена TikTok или возникла ошибка, очередь остановится на этом ролике. При повторном запуске проверьте его статус в TikTok перед повторной отправкой.

Это автоматизация интерфейса, а не официальный TikTok API. TikTok может потребовать повторный вход или CAPTCHA, а изменения интерфейса могут нарушить сценарий. Скрипт не обходит такие проверки: при необходимости пройдите их вручную в открытом браузере. Не публикуйте профиль `work/tiktok-profile` и не передавайте его другим — в нём хранится сессия аккаунта.

## Текущий результат
Лёгкая копия для просмотра в браузере: `output/clip_preview.mp4` (~8 МБ).

`output/clip.mp4` собран из **тестового** исходника (`make_test_source.sh`), т.к. `sample.mp4`
в репозитории нет. Выбран момент 00:00:50.000 — 00:01:30.000 исходника (40 с).
Субтитры в тестовом прогоне — заранее заданная SRT-фикстура, не распознавание речи.

## Find Twitch Clips (GitHub Actions)

Workflow `.github/workflows/find-twitch-clips.yml`, ручной запуск (`workflow_dispatch`):
Actions → **Find Twitch Clips** → Run workflow. Нужны секреты `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`.

Скрипт `scripts/find_twitch_clips.py` через Twitch Helix API берёт публичные клипы канала
(по умолчанию `strogo`) за последние 24 ч, фильтрует по категории `Grand Theft Auto VI`
и сортирует от новых к старым. Отчёт — в Summary запуска (название, ссылка, дата, длительность,
просмотры), JSON — артефакт `twitch-clips`. Статусы: `found` / `empty` (успех, 0 клипов) /
`error` (ошибка авторизации или API — job падает).
