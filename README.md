# narezki — прототип нарезчика стримов GTA 6

Делает из горизонтального стрима один вертикальный клип 1080×1920 (30–40 с) со звуком.

```bash
./run.sh            # sample.mp4 в корне → режет его; иначе генерирует тестовый исходник
```

Для реального стрима укажите регионы вебки и таймера в координатах исходника:

```bash
CAM=1400:760:500:300 TIMER=20:20:380:80 ./run.sh
```

Что делает `narezchik.py`:
1. FFmpeg-анализ: RMS звука по секундам (`astats`) + динамика картинки (`scdet`).
2. Выбор одного цельного окна 30–40 с с максимальной активностью (+ контекст до/после).
3. Рендер: вебка сверху (1080×608), геймплей снизу (центральный кроп 1080×1312),
   увеличенный таймер поверх геймплея, прожжённые субтитры.
4. Проверка через ffprobe (разрешение, длительность, аудиодорожка) → `output/clip.json`.

Субтитры: `<исходник>.srt` или `--srt`; если установлен `openai-whisper` — расшифровка автоматически.

## Публикация в TikTok (локально)

Для публикации через интерфейс TikTok Studio нужны Node.js 20+, установленный Playwright и его Chromium:

```bash
npm install
npx playwright install chromium
PUBLISH_TIKTOK=1 TIKTOK_CAPTION="Подпись к ролику #gta6" ./run.sh
```

При первом запуске откроется браузер: войдите в TikTok вручную. Сессия сохраняется локально в `work/tiktok-profile` и используется при следующих запусках. После загрузки видео проверьте его и подпись; публикация произойдёт только после ввода `PUBLISH` в терминале. Без `PUBLISH_TIKTOK=1` поведение `run.sh` не меняется.

Можно опубликовать уже готовый файл отдельно:

```bash
npm run publish:tiktok -- output/clip.mp4 --caption "Подпись к ролику"
```

Для нескольких готовых видео положите MP4 в `queue/`. Для каждого ролика можно добавить рядом одноимённый `.txt` с подписью; если файла с подписью нет, используется имя видео. Очередь сортируется по имени файла, после успешной публикации MP4 и его `.txt` перемещаются в `queue/published/`, чтобы не отправить их повторно. Первый ролик публикуется сразу, остальные — с паузой в 60 минут:

```bash
npm run publish:tiktok:queue
```

Пауза и папка настраиваются параметрами:

```bash
npm run publish:tiktok:queue -- --folder queue --delay-minutes 60
```

Очередь покажет список роликов и попросит один раз ввести `START`; затем она публикует без дополнительных подтверждений. Оставьте компьютер и терминал включёнными до завершения очереди. Если публикация не подтверждена TikTok или возникла ошибка, очередь остановится на этом ролике. При повторном запуске проверьте его статус в TikTok перед повторной отправкой.

Это автоматизация интерфейса, а не официальный TikTok API. TikTok может потребовать повторный вход или CAPTCHA, а изменения интерфейса могут нарушить сценарий. Скрипт не обходит такие проверки: при необходимости пройдите их вручную в открытом браузере. Не публикуйте профиль `work/tiktok-profile` и не передавайте его другим — в нём хранится сессия аккаунта.

## Текущий результат
Лёгкая копия для просмотра в браузере: `output/clip_preview.mp4` (~8 МБ).

`output/clip.mp4` собран из **тестового** исходника (`make_test_source.sh`), т.к. `sample.mp4`
в репозитории нет. Выбран момент 00:00:50.000 — 00:01:30.000 исходника (40 с).
Субтитры в тестовом прогоне — заранее заданная SRT-фикстура, не распознавание речи.

## Find Twitch Clips (GitHub Actions)

Workflow `.github/workflows/find-twitch-clips.yml` — только поиск и отчёт; он запускается вручную (`workflow_dispatch`):
Actions → **Find Twitch Clips** → Run workflow. Нужны секреты `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`.

Скрипт `scripts/find_twitch_clips.py` через Twitch Helix API берёт публичные клипы канала
(по умолчанию `strogo`) за последние 24 ч, фильтрует по категории `Grand Theft Auto VI`
и сортирует от новых к старым. Отчёт — в Summary запуска (название, ссылка, дата, длительность,
просмотры), JSON — артефакт `twitch-clips`. Статусы: `found` / `empty` (успех, 0 клипов) /
`error` (ошибка авторизации или API — job падает).

## Скачать и нарезать Twitch-контент локально

Workflow выше не скачивает видео и не запускает нарезчик. Для обработки существующих клипов и VOD используйте локальный пайплайн. Нужны FFmpeg/FFprobe, `yt-dlp`, Python 3 и Twitch API credentials:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp -n .env.example .env
# Fill TWITCH_CLIENT_ID and TWITCH_CLIENT_SECRET in .env
python3 scripts/process_twitch.py --channel strogo --category "Grand Theft Auto VI" --hours 24
```

Файл `.env` читается автоматически локальными Twitch-скриптами, не перезаписывая уже заданные переменные окружения, и исключён из Git. Не отправляйте его и не публикуйте секреты.

По умолчанию берётся один VOD канала за последние 24 часа. Для Twitch Clips категория проверяется по `game_id`; у VOD Helix может не вернуть категорию, поэтому при пустом `game_id` скрипт ищет точные упоминания названия игры в заголовке (например, `GTA 6` или `GTA VI`). VOD без названия игры в заголовке в таком случае не попадёт в обработку. Весь выбранный VOD проверяется чанками; количество моментов не ограничено фиксированным лимитом. Проходящие порог качества моменты с интервалом против дублей сразу передаются в монтаж трёх версий по 40, 35 и 30 секунд. Очередь TikTok может публиковать готовые видео, пока анализ продолжается. Скоринг сочетает всплески и смех в Twitch-чате, громкость/динамику видео и подсказки из распознанной Whisper речи. Это эвристический отбор, а не полноценное смысловое понимание: редкие инсайты без реакции чата или выраженных аудио/видеосигналов могут быть пропущены.

Для чата нужен [TwitchDownloaderCLI](https://github.com/lay295/TwitchDownloader/releases), доступный на macOS. Скачайте подходящий бинарник для Apple Silicon (arm64) или Intel, распакуйте и сделайте исполняемым:

```bash
chmod +x /path/to/TwitchDownloaderCLI
export TWITCHDOWNLOADERCLI=/path/to/TwitchDownloaderCLI
```

Либо добавьте его в `PATH`. Скрипт сохраняет JSON чата в `work/twitch/chat/` и использует потоковый разбор файла, не загружая все сообщения в память.

Порог отбора, минимальная дистанция между моментами и длина чанка настраиваются:

```bash
python3 scripts/process_twitch.py --min-score 0.45 --min-separation 90 --chunk-seconds 300
```

Чтобы автоматически публиковать готовые ролики, добавьте `--publish`. Скрипт попросит один раз ввести `START`; дальше новые ролики будут публиковаться по очереди без дополнительного подтверждения каждого видео. Между публикациями по умолчанию сохраняется пауза 60 минут:

```bash
python3 scripts/process_twitch.py --publish --delay-minutes 60
```

Очередь завершится после того, как будут опубликованы все найденные видео. При первой публикации в каждом аккаунте войдите в соответствующий профиль браузера; сессии сохраняются локально. Без `--publish` файлы только добавляются в очереди; их можно запустить позже стандартной командой ниже.

Установка `requirements.txt` включает Whisper и потоковый парсер чата `ijson`; Whisper скачает модель при первом запуске. Для обработки также существующих Twitch Clips укажите `--source both --max-clips 1` (Clips остаются в прежнем режиме выбора одного момента). Для пропуска распознавания и текстовых сигналов добавьте `--no-whisper`; анализ чата, аудио и динамики видео продолжится.

После проверки файлов в очередях запустите публикацию в три аккаунта:

```bash
npm run publish:tiktok:queue -- --accounts 3 --delay-minutes 60
```

Для каждого аккаунта откроется отдельный профиль браузера в `work/tiktok-profiles/account-N`. Войдите в соответствующий TikTok при первом запуске; профиль хранит сессию локально для следующих запусков. Очередь публикует последовательно, чередуя аккаунты, и ждёт заданный интервал между публикациями. TikTok всё равно может потребовать повторный вход или проверку и может ограничивать автоматизированные действия; гарантировать постоянную авторизацию нельзя.

Загрузка VOD может занять время и потребовать много места; лимиты меняются через `--max-clips` и `--max-vods`.
