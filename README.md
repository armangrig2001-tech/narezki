# narezki — прототип нарезчика стримов GTA 6

Делает из горизонтального стрима один вертикальный клип 1080×1920 (30–40 с) со звуком.

```bash
./run.sh            # sample.mp4 в корне → режет его; иначе генерирует тестовый исходник
```

Для реального стрима укажите регионы вебки и таймера в координатах исходника:

```bash
CAM=1400:760:500:300 TIMER=20:20:380:80 ./run.sh
```

Что делает `narezchik.py`:
1. FFmpeg-анализ: RMS звука по секундам (`astats`) + динамика картинки (`scdet`).
2. Выбор одного цельного окна 30–40 с с максимальной активностью (+ контекст до/после).
3. Рендер: вебка сверху (1080×608), геймплей снизу (центральный кроп 1080×1312),
   увеличенный таймер поверх геймплея, прожжённые субтитры.
4. Проверка через ffprobe (разрешение, длительность, аудиодорожка) → `output/clip.json`.

Субтитры: `<исходник>.srt` или `--srt`; если установлен `openai-whisper` — расшифровка автоматически.

## Текущий результат
Лёгкая копия для просмотра в браузере: `output/clip_preview.mp4` (~8 МБ).

`output/clip.mp4` собран из **тестового** исходника (`make_test_source.sh`), т.к. `sample.mp4`
в репозитории нет. Выбран момент 00:00:50.000 — 00:01:30.000 исходника (40 с).
Субтитры в тестовом прогоне — заранее заданная SRT-фикстура, не распознавание речи.

## Find Twitch Clips (GitHub Actions)

Workflow `.github/workflows/find-twitch-clips.yml`, ручной запуск (`workflow_dispatch`):
Actions → **Find Twitch Clips** → Run workflow. Нужны секреты `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`.

Скрипт `scripts/find_twitch_clips.py` через Twitch Helix API берёт публичные клипы канала
(по умолчанию `strogo`) за последние 24 ч, фильтрует по категории `Grand Theft Auto VI`
и сортирует от новых к старым. Отчёт — в Summary запуска (название, ссылка, дата, длительность,
просмотры), JSON — артефакт `twitch-clips`. Статусы: `found` / `empty` (успех, 0 клипов) /
`error` (ошибка авторизации или API — job падает).

## Render Twitch Clip (GitHub Actions)

Workflow `.github/workflows/render-twitch-clip.yml`, ручной запуск с параметром `clip_url`
(также запускается на PR, меняющих рендер). Скачивает публичный клип через `yt-dlp` без логина
и cookies; если Twitch не отдаёт видео — точная ошибка в Summary и запуск останавливается.
Дальше `narezchik.py --layout auto --keep-all`: весь клип (срезаются только пустые
начало/конец), оригинальный звук. Вебка стримера находится автоматически (`cam_detect.py`:
стабильное лицо + постоянная рамка) и ставится сверху на всю ширину, под ней — геймплей.
Не нашлась — запасная компоновка `full` (весь кадр + крупный план). Субтитры — только по
входу `subtitles`. Регионы `cam`/`timer` можно задать вручную. Результат — артефакт
`draka-vertical` и прямая ссылка в GitHub Release; превью и исходник — ветка `previews/<clip>`.

### Раскладка `tiktok` (по умолчанию)
1080×1920: вебка 1080×760 сверху (вся высота рамки — таймер стримера внутри вебки сохраняется,
по ширине — только лица и плечи), игра 1080×1160 снизу (без вебки, плашек донатов и миникарты,
окно плавно следует за действием), заголовок на стыке (`title_card.py`: заглавные, Montserrat Black
или Druk Super из `assets/fonts/`, главное слово жёлтым, тёмная плашка). Звук −14 LUFS
(двухпроходный loudnorm), фейд 3 кадра. Фрагмент: `--start/--end`.

## Clip Pipeline — автоматические нарезки (GitHub Actions)

Workflow `.github/workflows/clip-pipeline.yml`, код — `pipeline/`. Работает без ПК и ручной загрузки.

**Расписание:** раз в 10 минут (`cron */10`), плюс ручной запуск:
- `clip_url` — проверить конкретный клип (оценка + монтаж вне дневной квоты);
- `dry_run` — отчёт об отборе без финального рендера и без записи состояния;
- `force` — пересобрать клип из `clip_url`, даже если он уже смонтирован.

**Шаги одного запуска**
1. `plan` (только stdlib): Twitch Helix → клипы `strogo` за 48 ч в категории Grand Theft Auto VI,
   история просмотров, статус эфира. Если работы нет — тяжёлые шаги пропускаются.
2. `work`: исключение обработанных `clip_id` → группировка клипов одного события (`video_id` +
   пересечение таймкодов VOD; без таймкодов — близкое время создания, совпадение проверяется по звуку
   и репликам) → из группы версия с самым полным событием → до 24 подробных оценок в сутки
   (бюджет открывается по часам, часть мест — свежим клипам) → загрузка MP4 (yt-dlp) → faster-whisper
   (`small`, CPU, `int8`, язык авто, модель в кэше Actions) → кадры (начало, конец, смены сцены) →
   оценка Claude (если задан `ANTHROPIC_API_KEY`) или «отбор по метаданным» → дневная подборка →
   монтаж `narezchik.py --layout tiktok` с субтитрами из той же расшифровки → проверка ffprobe.

**Балл из 100 (Claude):** сила момента 25, понятность без контекста 25, реакция/развязка 20,
первые 2–3 с 15, динамика просмотров 10 (считает конвейер), пригодность для вертикали 5.

**Дневная подборка (сутки Asia/Yerevan):** цель 6 разных событий (5–7). 85+ — сразу в монтаж,
до конца эфира держим 2 места; 75–84 — резерв, добор после эфира (в марафон — после 23:00);
седьмой — только отдельный момент 85+; при близких баллах — разные типы событий. Без Claude пороги
85/75 не применяются: отбор по динамике просмотров, числу клипов одного события, свежести и
пригодности отрезка (в отчёте — «отбор по метаданным»).

**Состояние** — ветка `pipeline-state` (`state.json`): `clip_id`, ссылка, время создания, история
просмотров, балл, статус. Каждое изменение — атомарный push; перед оценкой и монтажом клип
«занимается» в ветке, поэтому ручной и плановый запуски не смонтируют один момент дважды.
Клип готов только после успешного рендера; при временной ошибке — до 3 попыток.

**Результат:** артефакт запуска `clips-<run_id>` (MP4 1080×1920 30–40 с, SRT, лист кадров),
в Summary — ссылка на клип, балл, причина выбора, таймкод монтажа, статус, пригодность для конкурса
(оригинальный таймер стрима в кадре).

Тесты логики отбора: `python -m unittest discover -s tests`.
